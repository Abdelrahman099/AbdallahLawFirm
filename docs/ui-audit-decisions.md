# UI audit decisions

## Current section/navigation redesign audit

The latest strict report in `output/qa/premium-ui-audit.json` was run against the absolute project root after the section and services-menu redesign. It contains **10 findings**, not a passing result: seven actionless-control detections and three existing consultation field policy/ownership findings. The Popover button in `ServicesDropdown.tsx` is the child of `PopoverTrigger asChild`; Radix provides its click, expanded state, Escape dismissal and focus restoration.

Runtime verification independently covers the desktop services disclosure, eight direct service routes, mobile services Accordion, Sheet close/navigation, audience selection, URL query restoration, reduced/full-motion content and Axe checks. No dummy click handlers or audit suppression were added. The native preferred-date ownership metadata and existing textarea resizing policy remain separate pre-existing consultation issues. This note does not claim whole-project strict compliance.

The former section styles and unused trust-strip component were removed. The mobile fixed consultation bar now appears after the homepage hero leaves view. The chosen default intro is `balance-onyx` («01 · لحظة الحكم»). Approved logo paths and the centered mobile lockup are preserved.

The following paragraphs retain the **earlier header/hero review snapshot** as historical evidence; its old counts and source locations describe that snapshot rather than the current report.

## Scope and evidence

The active change is the Arabic brand website's full-viewport service slider and responsive header. The consultation workflow is an existing, separate bounded form. The reviewed skill register is marketing/brand UI for the header and hero, with accessibility, layout stability, and reduced-motion requirements. This note does not claim whole-project strict compliance.

The existing strict static report contains nine errors: six actionless-button findings, one date-ownership finding, and two textarea findings. Report line numbers refer to the source snapshot at audit time and may have moved after the header changes.

The review used the actual component source and the shared shadcn/Radix owners. The auditor normalizes JSX tag names to lowercase and inspects a button's own attributes. It does not resolve `asChild` navigation or event handlers supplied by a Radix parent. No supported per-finding or business-wrapper exemption was found in the installed auditor. A no-op click handler would conceal these limitations rather than fix product behavior.

## Header and slider review boundaries

The new mobile screenshot shows booking on the physical left, Menu on the physical right, and no green top strip. Equal outer grid tracks geometrically center the compact approved logo. The compact SVG's internal whitespace creates a small optical offset; this is a presentation consideration, not permission to redraw the approved mark.

The source restores the mobile header immediately under `:focus-within` and while its menu is open. The hidden state applies only below 1024px; desktop keeps its translucent header visible and collapses only the top strip. Directional scroll thresholds, route reset, clamped scroll positions, and animation cleanup are present in the new hook. Runtime direction changes, focus restoration, narrow viewport sizing, reduced-motion behavior, and desktop preservation still require the project's browser verification; source inspection and a screenshot cannot establish those outcomes.

The existing bottom consultation bar is retained outside `/consultation`. Verify that it does not obscure the slider controls or focused elements. A fixed hero height or document-wide overflow clipping must not be introduced to force short screens into a single viewport; natural content overflow is intentional.

No source changes, browser tests, or build runs were performed as part of this read-only review. The only written review artifact is this note.
